### ROOT CAUSE — evidenced
**(b) PAYLOAD/OUTPUT-TOKEN TRUNCATION is the decisive failure.** The system
prompt makes the model **echo full title strings** inside every value's
`books[]`. At library scale, 3–5 richly-grounded values exceed the
`max_tokens:1024` **output** cap → `stop_reason: max_tokens` → truncated,
unparseable JSON → tolerant parse returns null → `[]` → silent empty state.
Input is NOT the limit (3488 tok is fine); **output is.** At 3 books output is
229 tok and completes normally — which is exactly why the R8-close 3-book
live-verify passed. **(a) exact-title grounding brittleness is a real latent
secondary** (any title-transcription drift drops a book from the ≥2 rule) that
would bite once truncation is removed; the shipped fix must cure both.

### Fix pre-proven on the SAME 130-book fixture (index-grounding POC, live proxy)

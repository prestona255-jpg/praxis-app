## Seam-hunt findings

1. **Group union is complete and disjoint** — confirmed programmatically:
   the 7 groups' members, deduplicated, exactly equal the 22-surface +
   1-layer set (23 = 23, zero duplicates, `diff` between the two sorted lists
   is empty). No surface fell out or landed in two groups.

2. **No fabricated counts found** — every rendered "N gaps" and "closed/total"
   traces to a real `grep -c` over a real, unchanged ledger file (see table
   above); nothing is hand-typed into the generator.

3. **Rollup orb-state logic is correct** — `group_rollup()`: unlit if
   `closed==0`; `u-orb--lit u-orb--amber` (bright) iff `closed>0 AND
   closed==total`; else `u-orb--soft u-orb--amber`. This matches the spec
   exactly. **Residual**: with every surface currently `untouched`, only the
   `unlit` branch is live-exercised in the actual output — the `soft` and
   `bright` branches are logically sound (read the code) but untested against
   real data yet. Not a defect, just an honest gap in current coverage.

4. **Gap-sort CAN mis-order on ties, and does** — `heat_group()`'s sort
   pipeline is `sort -rn` **without `-s`/`--stable`**. Verified directly
   (`printf … | sort -rn`): for tied gap-counts, GNU `sort -rn`'s `-r` also
   reverses the line-content tiebreak, producing **reverse-alphabetical**
   order among ties, not "list/map order" and not a stable pass-through. Two
   live instances in the current render: SHARE tile order is Account(6),
   Commons(2), Profile(1), **Walk(0), Reader(0)** — `walk` sorts before
   `reader` (reverse-alpha, `w`>`r`), even though `G_SHARE`'s declared order
   is `account profile commons reader walk` (reader before walk). Similarly
   ARRIVE's Onboarding(4) renders before About(4) — also reverse-alpha
   (`o`>`a`), coincidentally matching `G_ARRIVE`'s declared order this time,
   but only by coincidence, not because ties are stable. **This does not
   violate the stated contract** ("gap-sorted DESCENDING") since 0=0 and 4=4
   are still non-increasing — but the tie-break is an unintended,
   non-deterministic-looking side effect of using `-r` with no `-s`, not a
   deliberate design choice. Flagging as a residual worth a one-line `-s` fix
   in a future round (`sort -rns` or equivalent), not a blocker today.
